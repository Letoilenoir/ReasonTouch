# ReasonTouch Architecture Overview

## Project Structure
ReasonTouch is a modular Android/Kotlin application built around clear separation of concerns. The top‑level modules are:

- app — Compose UI, navigation, screen orchestration  
- core-audio — audio engine, DSP, mixing, rendering  
- core-midi — MIDI event routing, scheduling, quantization  
- core-composition — chord engine, bassline generator, progression logic  
- core-playback — transport, timing, metronome, playback state  
- core-music — music theory utilities (keys, scales, intervals)  
- core-ui — shared UI components  
- feature-chords — chord selection UI + integration with composition engines  
- feature-drums — drum pattern UI + integration with drum machine  
- feature-pianoroll — piano roll editor, MIDI editing  
- feature-export — audio/MIDI export workflows  

## High-Level System Flow
1. User interacts with Compose UI  
2. Composition engines generate musical structure  
3. MIDI events are produced  
4. MidiRouter distributes events  
5. PlaybackController manages transport  
6. AudioEngine renders audio frames  

## Key Architectural Principles
- Modularity — each domain (audio, MIDI, composition, playback) is isolated  
- Feature isolation — UI features depend only on the core modules they need  
- Unidirectional flow — UI → domain engines → MIDI → audio → playback  
- Testability — engines are pure Kotlin modules with no Android dependencies  
- Scalability — new features (e.g., synths, effects, sequencers) can be added without touching existing modules
